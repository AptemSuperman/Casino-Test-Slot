# PLAY THE AD

Пять коротких 3D-игр, по пять авторских эпизодов. Без сервера, аккаунта,
внешних ассетов, рекламы по умолчанию и ожидания открытия уровней.

## Открыть игру

Готовая сборка — **`dist/index.html`**. Это один самодостаточный HTML:
скрипты, стили и процедурная графика уже внутри. Для игры не требуются
npm, ключи API, модели или подключение к CDN. Нужен браузер с работающим WebGL 2.

Для наиболее предсказуемой работы ссылок и локальных сохранений используйте
обычный статический HTTP-хостинг либо локальный сервер:

```sh
npm run preview
```

Откройте `http://localhost:4173`. Сборка также подготовлена для открытия как
локальный HTML; в среде разработки именно навигацию `file://` запрещала
политика браузера, поэтому браузерные проверки загружали **тот же неизменённый
HTML** через Playwright `page.set_content`. Это ограничение среды проверки,
а не публикация сайта в интернете.

## Разработка

Нужен **Node.js 20.11+**; проверено на **Node.js 22.16.0**. Пакет не имеет
зависимостей исполнения или сборки; `npm install` не требуется.

```sh
npm run dev           # исходный проект: http://localhost:4173
npm test              # тесты правил, геометрии, сохранений и физики
npm run test:recipes  # все 25 решений + отрицательные сценарии + допуски ввода
npm run build         # dist/index.html и SHA-256 в dist/build.json
npm run preview       # сервер production-сборки
```

Проект можно разместить в любой подпапке: нет абсолютных путей к ассетам,
клиентского маршрутизатора с обязательной переадресацией или серверных API.
В production уходит **содержимое `dist/`**, а не исходники и тесты.

## Игры и управление

| Игра | Что делать | Управление |
|---|---|---|
| CROWD CASCADE | Распределить конечный запас зарядов между воротами и укреплениями | Удержание и горизонтальное перемещение; мышь или палец. На ПК также A/D или стрелки и пробел |
| POCKET HOLE | Начать с мелких предметов и вырасти до большой цели | Относительный drag/джойстик; WASD или стрелки |
| PINFALL TREASURE | Направить воду, лаву и золото безопасными каналами | Нажатия на кольца штифтов |
| SCREW STUDIO | Снимать доступные болты, собирать цветовые тройки и освобождать пластины | Нажатия на видимые болты; лоток ограничен тремя местами |
| RICOCHET WRECK | Прицелиться, использовать опоры, отражатели и каскад обломков | Потянуть назад в свободном месте поля и отпустить. Без движения выстрел не расходуется |

`R` — перезапуск, `N` — следующая игра, `P`/Escape — пауза, `M` — звук.
Все действия также доступны кнопками; выбор всех 25 уровней — в библиотеке.
При сворачивании вкладки игра останавливается; продолжение — кнопкой.

## Ссылки, сохранения и настройки

Пример адреса эпизода: `?game=screws&level=5`. Допустимые game:
`crowd`, `hole`, `pins`, `screws`, `wreck`; level — 1–5.

Сохранения: `localStorage`, ключ `play-the-ad:v1`, схема версии 1.
Победы, лучшие звёзды/время, посещённые эпизоды, качество графики и mute
сохраняются без аккаунта. Повреждённые или несовместимые данные безопасно
сбрасываются; отказ браузера в доступе к хранилищу не ломает игру.
Глобального рейтинга нет. Результаты локальны для браузера и адреса сайта.

Звук синтезируется Web Audio после первого пользовательского жеста. Режим
экономии отключает тени и ограничивает разрешение, но не меняет правила,
количество человечков, предметов и физические цели. Reduced motion уменьшает
декоративные эффекты. Музыкальной дорожки и рекламных SDK нет.

## Необязательный спонсор

По умолчанию выключен. Перед главным скриптом можно определить:

```html
<script>
window.PLAY_THE_AD_CONFIG = {
  sponsor: { enabled: true, name: "Название вашего спонсора" }
};
</script>
```

Отображается только короткая текстовая строка на экране результата.
Значение вставляется как текст, не как HTML. Никаких выдуманных рекламодателей,
трекеров, всплывающих окон и размещения поверх активных целей.

## Браузерные тесты

Python 3.10+ и Playwright нужны **только для тестирования**, не для игры:

```sh
python -m pip install playwright
python -m playwright install chromium
npm run build
npm run test:recipes
python tests/browser.py --mode both
```

На Linux без графического сеанса:

```sh
xvfb-run -a -s '-screen 0 1440x1080x24' python tests/browser.py --mode both
```

Переменные окружения: `BROWSER_EXECUTABLE` — путь к конкретному Chromium;
`HEADLESS=1` — headless; `SOFTWARE_WEBGL=1` — SwiftShader. В использованном
контейнере WebGL 2 работал в оконном Chromium под Xvfb, а не в headless.
На Windows можно использовать загруженный Playwright Chromium без Xvfb.

Проверки посылают реальные события мыши и сенсорного ввода. Наблюдательный
`window.__PLAY_AD__` предоставляет только снимок состояния и проекцию точки:
там нет установки победы, телепортации, изменения запасов или автопрохождения.
Часы Playwright подают кадры по 100 мс; сама игра делает шаги по 1/60 секунды.
Это проверяет правила и ввод, **но не доказывает 60 FPS**.

## Что измерено, а что нет

Не следует приравнивать успешный автотест к гарантии, что любой человек сочтёт
игру красивой и увлекательной. Эмуляция сенсорного ввода не заменяет реальный
телефон. В итоговом отчёте отдельно указаны проверенные браузерные сценарии,
реальная среда, результаты логики и непроверенные аппаратные условия.
